■ 全体のしくみ（はじめに）

--------------------------------------------------------------------------------



このアプリは、大きく2つの部分でできています。



  (1) 画面とデータの管理 …… Python（main.py など）

      本棚の画面、検索・絞り込み、タグ、Notion 連携、設定の保存を担当します。



  (2) 表紙と情報の取り出し …… Rust（src フォルダ）

      ZIP・PDF・フォルダ・URL から、表紙画像と

      題名・システム・人数・時間・概要・あらすじを読み取ります。

      Rust のプログラムは DLL（cover_extractor.dll）にして、main.py から呼び出します。



  起動の流れ:

    main.py を起動

      → cover_extractor.dll を探す

      → なければ src のソースから DLL を作る（cargo を使用。初回は数分かかります）

      → 本棚の画面を表示



  ※ main.py が呼び出すのは DLL かソースコードだけで、実行ファイル（.exe）は呼びません。

■ 一番上のフォルダ（Cover_extractor）

================================================================================



【アプリの本体（Python）】



  main.py

    アプリ本体です。これを起動します（python main.py）。

    主な中身:

      ・DLL の読み込み（なければソースから作り、main.py と同じ場所に置く）

      ・データベース（catalog.db）の読み書き

      ・本棚・図書カード・一覧表の3つの表示、本の大きさ（大・中・小）

      ・検索、タグ・人数・時間での絞り込み、並べ替え

      ・本を選んだときの見せ方（本をめくる／下からスライド／アニメーションなし）

      ・詳細・編集の画面、タグの管理、URL から取得した内容の確認画面

      ・Notion への書き出し・読み込みの画面

      ・画面の色・文字・木目の本棚などの見た目



  notion_sync.py

    Notion の API と通信する部分です。

      ・データベースの列の読み込み、ページの検索・作成・更新

      ・表紙画像のアップロード

      ・アプリの項目と Notion の列の自動対応付け

    main.py から読み込んで使います。



  app_settings.py

    設定ファイル（settings.ini）の読み書きを担当します。

      ・Notion のトークンを、この PC でしか戻せない形に暗号化して保存

        （Windows の DPAPI を使い、この PC の固有ID〈MachineGuid〉と

         今のユーザーに結び付けます）

    main.py から読み込んで使います。



【データ・設定（自動で作られる／更新される）】



  catalog.db

    登録したシナリオのデータベース（SQLite）です。

    題名・読み仮名・作者・システム・人数・時間・概要・あらすじ・表紙画像・

    タグ・お気に入り・プレイ状況・情報元の URL などが入っています。

    ※ 設定はここには保存しません（settings.ini に保存します）。

    ※ 消すと、登録したシナリオがすべて消えます。バックアップをおすすめします。



  settings.ini

    設定ファイルです。メモ帳で開けます。

      [display] … 表示の切り替え（本棚／カード／一覧表）、並べ替え、

                   本の大きさ、本を選んだときの見せ方

      [notion]  … Notion のトークン（暗号化済み）、データベースの URL、

                   列の対応付け

    ※ まだ設定を変えていない場合は、このファイルはありません。

      何か設定を変えると自動で作られます。

    ※ token の値は暗号化されているため、別の PC に写しても使えません

      （その場合は Notion の設定画面でトークンを入れ直してください）。

    ※ 消すと、設定が初期状態に戻ります。



  cover_extractor.dll

    src のソースから作った部品で、表紙と情報を取り出します。

    ※ 現在は作り直し待ちのため、フォルダにありません。

      次に main.py を起動したときに自動で作られます。

    ※ src を更新したときは、このファイルを消すと、次の起動で新しく作り直されます。



【DLL を作るのに必要なもの（Rust）】



  Cargo.toml

    Rust の部品（cover_extractor）の設計書です。

    名前・版・使う外部ライブラリ（ZIP・画像・PDF・通信など）を書いてあります。



  Cargo.lock

    使う外部ライブラリの正確な版の記録です。

    いつ作っても同じ版で DLL ができるようにします。消さないでください。



【その他】



  Gemini_Generated_Image_qpmdzqpmdzqpmdzq.jpg

    画面デザインの参考にした画像です。アプリでは使っていないので、

    不要なら消したり、別の場所へ移したりしても問題ありません。

■ src フォルダ（Rust のソースコード ＝ DLL の中身）

================================================================================



表紙を探す・情報を読む処理の本体です。main.py は、ここから作った DLL を呼び出します。



  lib.rs

    部品全体の入り口です。各ファイルの機能をまとめて外に見せます。



  ffi.rs

    DLL として Python（main.py）から呼び出すための窓口です。

    「表紙を取り出す」「情報を取り出す」「URL から取り出す」などの関数があります。



  extractor.rs

    表紙を取り出す処理の流れをまとめたものです。

    （中身を一覧にする → 表紙らしさの点数を付ける → 一番点の高いものを採用 →

      見つからなければ仮の表紙）



  select.rs

    表紙の候補（画像・PDF の1ページ目）を集めて、点数を付けます。



  rules.rs

    表紙の判定ルール（rules.toml）を読み込み、ファイル名をキーワードと照らし合わせます。



  rules.toml

    表紙の判定ルールの設定です。

    「cover」「表紙」などの名前は加点、「差分」「立ち絵」などは減点、のような

    決まりを書いてあります。ここを変えると、表紙の選び方を調整できます。



  info_rules.toml

    シナリオ情報の読み取りルールの設定です。

    「推奨人数」「プレイ時間」「推奨技能」「あらすじ」「トレーラー」などの

    見出しの言葉や、システム名（CoC・マーダーミステリーなど）を書いてあります。



  names.rs

    ZIP の中のファイル名の文字コード（Shift_JIS など）を読み、比べやすい形にそろえます。



  pdf.rs

    PDF の読み込み（表紙にするページの画像化と、文字の取り出し）を担当します。



  thumbnail.rs

    画像を読み込み、向きを直し、縮小して、JPEG のサムネイルにします。



  placeholder.rs

    表紙が見つからなかったときの、本の形をした仮の表紙を描きます。



  limits.rs

    大きすぎるファイルや壊れたデータで止まらないよう、読み込みの上限を決めています。



  error.rs

    エラーの種類と、そのメッセージの定義です。



────────────────────────────────────────

  src\info フォルダ … シナリオ情報（題名・あらすじなど）の読み取り

────────────────────────────────────────



  mod.rs

    この機能の入り口です。



  text.rs

    文書（txt・md・html・json・pdf）から、文字を1行ずつ取り出します。

    PDF の2段組みの判定もここで行います。



  normalize.rs

    取り出した文字をそろえます（全角英数字→半角、記号のゆれの統一など）。



  extract.rs

    文書を読んで、題名・システム・人数・時間・概要・あらすじを組み立てます。

    「タイトル：」の見出しを優先する、あらすじの候補を選ぶ（あらすじ・トレーラー＞

    概要の文章＞背景＞導入）、などの判断をしています。



  fields.rs

    人数（「2〜4人」）や時間（「4〜6時間」）などの値の読み方です。



  rules.rs

    読み取りルール（info_rules.toml）を読み込みます。



────────────────────────────────────────

  src\source フォルダ … シナリオの入れ物の読み込み

────────────────────────────────────────



  フォルダ・ZIP・単体のファイルを同じ方法で扱えるようにする部分です。



  mod.rs ………… 共通の決まり（入れ物の中身の一覧・読み出し）

  folder.rs …… 通常のフォルダを読みます（深すぎるフォルダは読みません）

  zip_source.rs … ZIP を展開せずに、必要なファイルだけを読みます

  file.rs ……… PDF などを1つだけ指定したときに読みます



────────────────────────────────────────

  src\web フォルダ … URL（BOOTH など）からの取得

────────────────────────────────────────



  mod.rs

    URL から情報を取り出す処理の入り口です。サイトに合った取り出し方を選びます。

    pixiv など新しいサイトに対応するときは、ここに取り出し方を追加します。



  booth.rs

    BOOTH の商品ページから、商品名・説明文（▼あらすじ などの欄）・画像を読みます。



  generic.rs

    BOOTH 以外のサイトから、ページの題名・説明・画像を読みます。



  http.rs

    インターネットからの読み込み（大きさの上限付き）を担当します。

  使い方の例（このフォルダで実行）:

    cargo run --release --example info -- "M:\シナリオ\作品.zip"

■ target フォルダ（DLL を作るときの作業場所）

================================================================================



  Rust のソースから DLL を作るときに、途中のファイルが置かれる場所です。

  現在 約 800MB あります。



  ・自動で作られるので、消しても問題ありません（消すと容量が空きます）。

  ・ただし消すと、次に DLL を作るとき、最初から作り直すので時間がかかります。

  ・中身を手で変更する必要はありません。

■ 消してよいもの・消してはいけないもの（まとめ）

================================================================================



  消してはいけない（アプリが動かなくなる）

    main.py / notion_sync.py / app_settings.py

    Cargo.toml / Cargo.lock / src フォルダ（DLL を作るのに必要）



  消すとデータが失われる（バックアップをおすすめ）

    catalog.db …… 登録したシナリオがすべて消える

    settings.ini … 設定が初期状態に戻る（Notion の設定もやり直し）



  消しても自動で作り直される

    cover_extractor.dll …… 次の起動で作り直し（数分かかる）

    target フォルダ ……… 次に DLL を作るときに作り直し

    __pycache__ フォルダ … Python が自動で作る一時ファイル（ある場合）



  アプリの動作には不要

    examples フォルダ / tests フォルダ …… 開発用

    Gemini_Generated_Image_….jpg ……… デザインの参考画像



  別の PC へ移すとき

    フォルダごとコピーすれば動きます（DLL は移した先で作り直されます）。

    ただし settings.ini の Notion のトークンは、暗号化の都合で移した先では読めません。

    Notion 連携の設定画面で、トークンだけ入れ直してください。
